# בוט התראות גשם לגבעת שמואל

בוט שקורא את מכ"ם הגשם של [RainViewer](https://www.rainviewer.com), מזהה גשם שמתקרב לגבעת שמואל ושולח התראה בטלגרם בשלושה שלבים: **מוקדמת** (עד 45 דקות), **מיידית** (עד 20 דקות) ו**כעת**.

גרסה נוכחית: **3.2-beta**.

## מה חדש ב-3.2

- **התראת "מעקב"** כשעה לפני: מערכת גשם בים שתגיע בעוד 45-90 דקות. נשלחת רק כשכל התנאים מתקיימים: ודאות 3 מתוך 3, תנועה איכותית, מערכת של 200+ קמ"ר שלא נחלשת, ותחזית המודלים מסכימה. לכל היותר פעם ב-3 שעות, ולא משפיעה על ההשתקה של ההתראות הרגילות.
- **"הגשם מתחזק"**: באמצע הגשם, כשהוא הופך לחזק (40+ dBZ) וההתראה האחרונה הייתה על גשם חלש או בינוני. פעם אחת (`sent_why: intensify`).
- **טלגרם עמיד יותר**: על 429 מחכים עד 15 שניות ומנסים שוב; תגית HTML שבורה לא מפילה התראה, היא נשלחת כטקסט רגיל.
- **מכ"ם**: רשימת הפריימים ממוינת ומסוננת מכפילויות.
- **נוסח חדש לכל ההודעות**: כותרת קצרה, שעה בשעון + בעוד כמה דקות, עוצמה ומגמה בשורה אחת, ודאות ואישור ממקור נוסף בשורה אחת, וטיפ מעשי (כביסה, מטרייה).
- `status.json`: שדה אופציונלי חדש `watch` (`{"eta": [lo, hi], "peak_dbz", "front_km"}` או null).

## מה היה חדש ב-3.1

- **תחזית מודלים (Open-Meteo)** כ"דעה שנייה": מאשרת התראת מערכת בוודאות בינונית כשהתנועה עקבית והתחזית צופה גשם בחלון ההגעה, ושולחת "צפוי גשם בשעות הקרובות" (לכל היותר פעם ב-12 שעות). התחזית לבד אף פעם לא שולחת התראת מכ"ם.
- **מד הגשם בבית דגן** (השירות המטאורולוגי): מאשר "כעת" בוודאות גבולית. פעיל רק אם מוגדר הסוד `IMS_TOKEN`.
- **בריאות המכ"ם**: אם אין מכ"ם תקין 30 דקות, נשלחת הודעה אחת, ועוד אחת כשהוא חוזר. פריים שחסר לו אריח נזרק, והבוט ממשיך עם 3 פריימים.
- **מגמת עוצמה**: מתחזק / נחלש / יציב בכל התראה. תא קטן שגווע בדרך לא מתריע.
- **תאים שמתפתחים במקום** ליד הגבעה (עד 6 ק"מ, 30+ dBZ, בשני פריימים, ולא היו שם לפני 30 דקות).
- **"הגשם עבר"**: הודעה אחת אחרי התראת "כעת", כשאין הד ב-10 ק"מ ואין גשם בדרך.
- **הרצה חוזרת**: בכל התראה או חשד לפספוס נשמר גם קובץ `npz` עם נתוני המכ"ם, ו-`python -m rainbot.replay file.npz` מריץ עליו את הניתוח מחדש.
- הקוד מחולק לקבצים בתיקייה `rainbot/` (`bot.py` נשאר נקודת הכניסה).

### הפעלת מד הגשם (אופציונלי)

1. מבקשים מפתח API חינמי מהשירות המטאורולוגי (ims.gov.il, "שירותי מידע" / API).
2. ב-GitHub: Settings ← Secrets and variables ← Actions ← New repository secret, בשם `IMS_TOKEN`.
3. זהו. תחנה אחרת: משתנה `IMS_STATION` (ברירת מחדל 54, בית דגן).

## איך זה רץ

- `bot.py` רץ ב-GitHub Actions (`.github/workflows/weather.yml`) כל 5 דקות. ההפעלה העיקרית מגיעה מ-cron-job.org, וה-cron של GitHub הוא גיבוי.
- המצב (`state/state.json`, `state/history.jsonl`) נשמר ב-cache של Actions בין ריצות.
- כל ריצה מפרסמת `status.json` לענף `status`, והדשבורד ב-`docs/index.html` (GitHub Pages) קורא אותו.
- תמונות מכ"ם של התראות ושל "חשד לפספוס" נשמרות כ-artifact של הריצה ל-14 יום.

| מערכות | חזיתות גשם גדולות שמגיעות מהים | ציון ודאות 3 מתוך 3 (תנועה עקבית, גודל, יציבות), או 2 עם תנועה עקבית ואישור מהתחזית |

## מתי נשלחת התראה (השתקה)

כל ריצה רושמת בלוג (`history.jsonl`) את השדות `sent_why` (למה נשלחה) או `hold` (למה לא):

| ערך | משמעות |
| --- | --- |
| `first`, `new_episode` | התראה ראשונה, או שעברו 60 דקות בלי זיהוי שעובר את הסף |
| `escalation` | החמרה: מוקדמת ← מיידית ← כעת |
| `new_wave` | אחרי "כעת" לא נצפה גשם מעל הגבעה 20 דקות, וגל חדש מתקרב |
| `cooldown_over` | אותו שלב חוזר אחרי 90 דקות |
| `intensify` | באמצע הגשם הוא הפך לחזק (3.2) |
| `cooldown` | אותו שלב (או נמוך יותר) לפני שעברו 90 דקות |
| `same_frame` | כבר נשלחה התראה על אותו פריים מכ"ם |
| `low_score`, `no_rain` | יש גשם אבל לא בוודאות מספיקה, או שאין גשם |
| `send_failed` | טלגרם לא קיבל את ההודעה |

שדות נוספים בלוג מ-3.1: `trend` (מגמה), `boost` (`forecast` / `ims` כשמקור נוסף אישר), `fc_agree`, `fc_prob`, `ims_mm`, `frames`, `extra` (הודעות מערכת שנשלחו: `radar_down`, `radar_up`, `rain_end`, `headsup`, `watch`), `watch` (מועמד למעקב ואם עמד בתנאים), `radar_err`.

אם טלגרם לא עונה בזמן (ReadTimeout), ההודעה נחשבת "כנראה נשלחה" ולא נשלחת שוב.

## הרצה מקומית

```bash
pip install -r requirements.txt
python bot.py --dry-run --png out.png --save-frames out.npz   # בלי שליחה ובלי שמירת מצב
python -m rainbot.replay out.npz          # הרצה חוזרת על נתונים שמורים
python -m unittest discover -s tests -v   # בדיקות, בלי רשת
```

במצב `--dry-run` הבוט מדפיס את ההודעה שהייתה נשלחת, ואם לפי המצב השמור היא הייתה נשלחת בפועל.

## משתני סביבה

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (חובה בריצה רגילה), `STATE_DIR`, `STATUS_DIR`, `OUT_DIR`, `IMS_TOKEN`, `IMS_STATION` (אופציונליים), `FORECAST=0` (כיבוי התחזית).
